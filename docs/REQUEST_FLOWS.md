# Request flows from current code

DEEP is a separate service: executor token → typed PUBLIC request → durable singleton claim →
route metadata preflight → dispatch marker → pinned OmniRoute Responses HIGH → sanitized text.
No FREE routing or fallback is involved. Continuation is explicitly unavailable in text-only
mode. See [exact DEEP contract](DEEP_BACKEND.md). The former portal-deep FREE alias is removed.

Names after `create_app.` are nested functions in [gateway.py](../mg_ai/gateway.py).
Uvicorn invokes `mg_ai.gateway:create_app --factory` from [Dockerfile](../gateway/Dockerfile).
All chat paths start with `Boundary.__call__` (1 MiB body cap, 10-second read deadline).

## A. Successful free request

`POST /v1/chat/completions` → `gateway.create_app.chat` → `create_app.authenticate`
→ `ChatRequest.model_validate_json` (Pydantic; validators in [requests.py](../mg_ai/requests.py))
→ `ChatRequest.capabilities` → client route/minimum-privacy/grant/capability checks in `chat`
→ `State.check_duplicate` when a client idempotency key is supplied
→ `routing.select` → `Candidate.available`, `State.health`, `State.capacity`, `Capacity.blocks`
→ `State.admit` → `State.provider_enabled` pre-dispatch recheck → `State.execution(DISPATCHED)` → `LiteLLMAdapter.execute`
→ private LiteLLM `POST /v1/chat/completions` → provider → normalized `Result(SUCCESS)`
→ `State.record` → `observability.emit` → `State.execution(SUCCESS)`
→ JSON response with logical route name, or `gateway.sse`.

Registry alias chooses the LiteLLM deployment generated by `proxy_config.render`; LiteLLM
does provider translation, not MG policy selection. Response streaming is buffered: the
adapter asks for `stream=False`, validates the complete answer, then MG emits SSE chunks.

## B. 429 classified as safe rejection

`LiteLLMAdapter.execute` receives HTTP 429 → matching unexpired `Candidate.retry_429_review`
for provider/model/LiteLLMAdapter → `Result(RATE_LIMITED_SAFE,
UPSTREAM_RATE_LIMITED)` → `State.record` records cooldown (Retry-After bounded to 1–3600 s)
→ `State.execution(SAFE_FAILURE)` → next already-selected candidate in `chat`.

Without reviewed evidence, 429 → EXECUTION_AMBIGUOUS / UNREVIEWED_429_ACCEPTANCE → flow D;
no fallback. No real provider currently has approved evidence. Review describes provider
contract semantics, not a per-request acceptance receipt. A Gateway admission
429 (`State.admit`: CLIENT_RATE_LIMITED / REQUEST_BUDGET_EXHAUSTED) dispatches nothing.

## C. Safe fallback

`LiteLLMAdapter.execute` → connect/pool failure (`PROXY_NOT_REACHED`) or 401/403/404
(`UPSTREAM_CONFIG_REJECTED`) → `SAFE_TO_RETRY` → `State.record`
→ `State.execution(SAFE_FAILURE)` → `chat` attempts next candidate → success path A.
At most three candidates are attempted. If exhausted: `MGError(NO_ELIGIBLE_FREE_MODEL,503)`.
There is no sleep/reselection loop and no LiteLLM fallback. A duplicate key does not retry:
`State.check_duplicate` returns 409 even after SAFE_FAILURE.

## D. Ambiguous dispatch

`State.execution(DISPATCHED)` → `LiteLLMAdapter.execute` → non-connect HTTP exception,
HTTP >=500 / 408 / 409, oversized response or invalid response/schema
→ `EXECUTION_AMBIGUOUS` → `State.record` → `State.execution(AMBIGUOUS)`
→ `MGError(EXECUTION_AMBIGUOUS,502,reconciliation=True)` → `MGError.body`
with `execution_state=RECONCILIATION_REQUIRED`. No next candidate.
An exception escaping the adapter also marks AMBIGUOUS in `chat`. A process crash can leave
DISPATCHED; the same key is still blocked. Preserve the database and request ID.

## E. No eligible free model

`chat` → `routing.select` → empty list → `MGError(NO_ELIGIBLE_FREE_MODEL,503)`.
No admission/dispatch on this path. Empty selection can mean disabled model, absent key,
expired free evidence, insufficient score/capability/context, privacy mismatch, cooldown or
fresh blocking capacity. Readiness uses policy default privacy and output 1024, so it is
an estimate for that profile, not a guarantee for every actual request.

## F. Developer / Cline-compatible request

Developer MG token → `GET /v1/models` → `create_app.models` → `authenticate`
→ policy's logical route list. `POST /v1/chat/completions` → flow A, including tool/schema
checks → normalized tool proposal returned to client. MG does not execute tools or restrict
the client's subsequent filesystem/shell actions. `scope_guard.check` is a separate local
tool, not a middleware hook. Endpoint contract passed in saved certification; Cline itself
was not driven. No `/v1/responses` API exists in this app.

## G. Live benchmark (external inference; not executed for this handover)

`python -m mg_ai.live_benchmark prepare` → `live_benchmark.main` → `approved_dataset` → `eligible`
→ `proxy_config.render` → ignored isolated LiteLLM YAML.

Manual --live/--approved-by runner → `live_benchmark.main` → `run` → `approved_dataset`
→ `State.provider_enabled` in shared control store → `eligible` / key-present guard
→ `State.admit` → per-fixture `payload` → shared `State.provider_enabled` recheck → `State.execution(DISPATCHED)`
→ `LiteLLMAdapter.execute` → separate private LiteLLM → provider
→ `score_case` → `run.persist` (atomic report update) → `summarize`.
Any non-SUCCESS stops the run; ambiguous becomes RECONCILIATION_REQUIRED, other failure FAILED.
Success completes as COMPLETED. `model_intelligence.recommendations` reads completed reports
and recomputes threshold scores; it never changes the registry. A failed run can contain useful
partial scores, but is excluded by the recommendation generator.

The runner requires a fresh (<24 h) zero-price pinned `:free` catalog entry and public synthetic
fixtures. It intentionally accepts disabled candidates for evaluation and does not call
`routing.select`, `Capacity.blocks` or Gateway client policy. Its journal uses a benchmark
client identity and run-level admission, not per-fixture production request budgets. Dataset
bytes must match the reviewed fixed-path manifest and are captured before use; an arbitrary
fixture edit cannot silently flow into the run. Shared provider control does not merge the journals.
